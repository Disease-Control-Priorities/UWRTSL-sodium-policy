## Core concept

The current `06` treats sodium as a single pool and applies one blended `salteff` fraction to the
whole `salt` column. Replace this: split baseline sodium into five sources, apply each intervention's
documented relative reduction to only its target source(s), then collapse back to a single
total-intake reduction fraction:

    total_reduction_fraction = Σ_over_sources ( source_share_s × effect_size(intervention, s) )

That resulting fraction is exactly the `salteff` that the existing `calculate_sodium_impact_etihad()`
(saltmet = "percent") already expects. So EVERYTHING downstream of the salteff fraction stays
UNCHANGED: `calculate_sodium_impact_etihad()`, `project.all()`, the state-transition loop, the
output schema, the parallel loop structure, and `validate_intervention_results()`. The new
source logic lives entirely upstream in the scenario configuration.

## CLARIFICATION 4 — Intervention selection (single, all, or user-specified subset)

The model must support running ANY combination of interventions, controlled by the user:

- A SINGLE intervention on its own (e.g. just `fopl`).
- ALL interventions blocked together as one combined package (compose per source with
  `1 − Π(1 − eff_i,s)` so multiple policies hitting the same source don't double-count).
- Any USER-SPECIFIED SUBSET of interventions (e.g. `c("fopl", "salt_targets")` run as one
  combined package, or as separate scenarios — see below).

Implement this with a single user-facing control at the top of the script — a variable such as:

    # Which interventions to model. Options:
    #   - a single name:            "fopl"
    #   - a character vector:       c("fopl", "salt_targets", "fiscal")
    #   - the keyword "all":        every defined intervention, composed into one package
    selected_interventions <- "all"

Behavior:
- `compute_total_efficacy()` already accepts a vector of intervention names and composes them per
  source, so a single name, a subset, or all names all flow through the same code path — a single
  intervention is just the one-element case, and "all" expands to every defined intervention.
- Build `scenario_configs` dynamically from `selected_interventions` rather than hard-coding a fixed
  scenario list:
    * Always include `baseline` (salteff = 0).
    * If the user wants each intervention scored INDIVIDUALLY, generate one scenario per name in the
      vector (plus optionally a combined `full_package` scenario).
    * If the user wants them COMBINED, generate a single package scenario from the whole vector.
  Expose this with a second control, e.g.:

    # "individual" = one scenario per selected intervention (+ baseline)
    # "combined"   = all selected interventions modelled together as one package (+ baseline)
    # "both"       = individual scenarios AND a combined package
    scenario_mode <- "both"

- "all" as the value of `selected_interventions` must resolve to the full set of defined
  interventions (public_procurement, media_campaign, fopl, salt_targets, fiscal, lss).
- Validate that every name in `selected_interventions` is a defined intervention; error clearly if not.
