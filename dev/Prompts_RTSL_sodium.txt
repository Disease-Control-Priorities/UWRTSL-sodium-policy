## Core concept

The current `06` treats sodium as a single pool and applies one blended `salteff` fraction to the
whole `salt` column. Replace this: split baseline sodium into five sources, apply each intervention's
documented relative reduction to only its target source(s), then collapse back to a single
total-intake reduction fraction:

    total_reduction_fraction = Σ_over_sources ( source_share_s × effect_size(intervention, s) )

That resulting fraction is exactly the `salteff` that the existing `calculate_sodium_impact_etihad()`
(saltmet = "percent") already expects. So EVERYTHING downstream of the salteff fraction stays
UNCHANGED: `calculate_sodium_impact_etihad()`, `project.all()`, the state-transition loop, the
output schema, the parallel loop structure, and `validate_intervention_results()`. The new
source logic lives entirely upstream in the scenario configuration.

## CLARIFICATION 4 — Intervention selection (single, all, or user-specified subset)

The model must support running ANY combination of interventions, controlled by the user:

- A SINGLE intervention on its own (e.g. just `fopl`).
- ALL interventions blocked together as one combined package (compose per source with
  `1 − Π(1 − eff_i,s)` so multiple policies hitting the same source don't double-count).
- Any USER-SPECIFIED SUBSET of interventions (e.g. `c("fopl", "salt_targets")` run as one
  combined package, or as separate scenarios — see below).

Implement this with a single user-facing control at the top of the script — a variable such as:

    # Which interventions to model. Options:
    #   - a single name:            "fopl"
    #   - a character vector:       c("fopl", "salt_targets", "fiscal")
    #   - the keyword "all":        every defined intervention, composed into one package
    selected_interventions <- "all"

Behavior:
- `compute_total_efficacy()` already accepts a vector of intervention names and composes them per
  source, so a single name, a subset, or all names all flow through the same code path — a single
  intervention is just the one-element case, and "all" expands to every defined intervention.
- Build `scenario_configs` dynamically from `selected_interventions` rather than hard-coding a fixed
  scenario list:
    * Always include `baseline` (salteff = 0).
    * If the user wants each intervention scored INDIVIDUALLY, generate one scenario per name in the
      vector (plus optionally a combined `full_package` scenario).
    * If the user wants them COMBINED, generate a single package scenario from the whole vector.
  Expose this with a second control, e.g.:

    # "individual" = one scenario per selected intervention (+ baseline)
    # "combined"   = all selected interventions modelled together as one package (+ baseline)
    # "both"       = individual scenarios AND a combined package
    scenario_mode <- "both"

  interventions (public_procurement, media_campaign, fopl, salt_targets, fiscal, lss).

### Step 3f — SSaSS trial-RR pathway (approach B), applied to STROKE causes only

This is the potassium-inclusive primary effect. It **replaces** the sodium→SBP
mechanism for the reached, eligible population *when `lss_method == "trial_rr"`*,
and it writes to case fatality (which is currently a no-op).

**Source:** Neal B, Wu Y, Feng X, et al. Effect of Salt Substitution on
Cardiovascular Events and Death. NEJM 2021;385:1067–1077. DOI:
10.1056/NEJMoa2105675.

**Trial RRs (for reference):** total stroke 0.86; fatal stroke 0.77; nonfatal
stroke 0.90; vascular death 0.87; ischemic stroke 0.93; hemorrhagic stroke 0.69.

**CRITICAL mapping decision — read carefully before coding.** The paper's
"approach B" says "apply 0.77 to fatal stroke, 0.90 to nonfatal stroke." But THIS
model does not track fatal vs nonfatal stroke as separate outcome streams — it
tracks stroke **incidence** (`IR`) and stroke **case fatality** (`CF`) per cause.
The ONLY translation of approach B onto that structure that does not double-count
is:

- **Incidence multiplier = nonfatal-stroke RR = 0.90**, applied to `istroke` and
  `hstroke` incidence. (Nonfatal stroke is the closest proxy for "fewer strokes
  occur," which is what IR represents.)
- **Case-fatality multiplier = fatal/nonfatal = 0.77 / 0.90 = 0.856**, applied to
  `istroke` and `hstroke` case fatality. This is the *conditional* extra mortality
  benefit beyond fewer strokes occurring. The fatal-stroke RR (0.77) already embeds
  the incidence reduction, so applying 0.77 directly to CF on top of a 0.90
  incidence cut would double-count — hence the ratio. This IS the "formally derived
  and justified" conditional CF effect that approach A leaves open; we derive it
  here so the potassium mortality benefit is captured without double-counting.
- **Do NOT also apply the total-stroke RR (0.86)** anywhere — 0.90 (incidence) ×
  0.856 (CF) already reproduces the combined stroke effect.
- **Non-stroke causes (`ihd`, `hhd`, `aod`): no direct trial effect in the base
  case.** SSaSS was powered on stroke/MACE. Leave these to the sodium→SBP channel
  or unchanged; do not invent an IHD RR.

Implement as a branch. After Step 4 (scale-up produces `salt_reduction`) compute
the reached fraction, and in the results assembly use the trial multipliers
instead of the sodium→SBP incidence effect for stroke causes:

```r
# ---- LSS trial-RR pathway (potassium-inclusive; approach B) ----------------
apply_trial_rr <- !is.null(lss_method) && lss_method == "trial_rr" &&
                  !is.null(lss_reach)  && lss_reach != "none"

if (apply_trial_rr) {
  # SSaSS relative risks (NEJM 2021;385:1067-77), mapped to this model:
  RR_STROKE_INCIDENCE <- 0.90            # nonfatal-stroke RR -> incidence
  RR_STROKE_CF        <- 0.77 / 0.90     # conditional CF effect (= 0.856)
  stroke_causes       <- c("istroke", "hstroke")

  # Reached fraction, ramped identically to the sodium scale-up so LSS shares
  # the 2026->2030 window:
  dt_baseline[, ramp := fifelse(
    year < saltyear1, 0,
    fifelse(year > saltyear2, 1,
            (year - saltyear1 + 1) / (saltyear2 - saltyear1 + 1)))]

  dt_baseline[, reached := 0]
  if (lss_reach == "all") {
    dt_baseline[, reached := lss_coverage * ramp]
  } else {  # htn_diagnosed / htn_treated: eligible bins only
    dt_baseline[bp_cat %in% hypertensive_bins, reached := lss_coverage * ramp]
  }

  # Blend RR toward 1 by reached fraction: effective RR = 1 - reached*(1-RR).
  dt_baseline[, eff_ir_trial := 1]
  dt_baseline[, eff_cf_trial := 1]
  dt_baseline[cause %in% stroke_causes,
              eff_ir_trial := 1 - reached * (1 - RR_STROKE_INCIDENCE)]
  dt_baseline[cause %in% stroke_causes,
              eff_cf_trial := 1 - reached * (1 - RR_STROKE_CF)]
}
```

Then, in the results assembly (Steps 8–9), branch on `apply_trial_rr`. When TRUE,
use the trial multipliers **instead of** the sodium→SBP incidence effect, and set
case fatality from the trial (overriding the `CF_new := CF; eff_cf := 1` no-op):

```r
if (apply_trial_rr) {
  # Incidence: apply trial RR to baseline bin incidence, then population-weight
  # (parallels Step 8), rather than the SBP-mediated cut.
  dt_baseline[, IR_bin_new := IR_bin * eff_ir_trial]
  dt_baseline[, IR_new := sum(IR_bin_new * prob),
              by = .(age, sex, location, cause, year)]
  dt_baseline[year < saltyear1, IR_new := IR]
  dt_baseline[, eff_ir := IR_new / IR]

  # Case fatality: conditional trial effect on stroke CF (was a no-op).
  # Population-weight the CF multiplier the same way, so partially-reached bins
  # average correctly.
  dt_baseline[, CF_bin_new := CF * eff_cf_trial]
  dt_baseline[, CF_new := sum(CF_bin_new * prob),
              by = .(age, sex, location, cause, year)]
  dt_baseline[year < saltyear1, CF_new := CF]
  dt_baseline[, eff_cf := CF_new / CF]
  dt_baseline[is.na(eff_cf), eff_cf := 1]
} else {
  # existing sodium->SBP Steps 8-9 unchanged:
  # IR_new / eff_ir from etihad_effect_sodium; CF_new := CF; eff_cf := 1
}
```
